# PS4 FFPFSC 0.2.6

> Надёжная отмена, выбор FFPFSC/exFAT, управляемые потоки и корректная
> AES-CBC-распаковка NP-метадаты.
>
> Reliable cancellation, FFPFSC/exFAT selection, configurable workers, and
> correct AES-CBC extraction of NP metadata.

## Загрузки / Downloads

- `PS4-FFPFSC-v0.2.6-macos-arm64.zip` — macOS 13+, Apple Silicon.
- `PS4-FFPFSC-v0.2.6-windows-x64.zip` — Windows 10/11 x64.
- Файлы `.sha256` содержат контрольные суммы архивов.
- `.sha256` files contain archive checksums.

## Русская версия

### Добавлено

- **Выбор формата результата.** По умолчанию создаётся сжатый `.ffpfsc`.
  Дополнительно можно выбрать несжатый raw `.exfat`.
- **Прямое создание exFAT.** Несжатый образ создаётся как единственный
  partial-файл и после проверки атомарно публикуется под итоговым именем.
  Проверка выборочно читает структуру файловой системы, обязательные игровые
  файлы и метаданные, поэтому для верификации не создаётся вторая полная копия
  образа.
- **Выбор числа потоков MkPFS.** Для сжатия FFPFSC доступно от 1 потока до
  количества логических процессоров системы. По умолчанию используется
  половина логических процессоров, но не менее одного. Это оставляет системе
  ресурсы во время длительной сборки.
- **Регрессия NP-метадаты.** Нативный тест воспроизводит случай, когда
  объявленный размер `npbind.dat` равен 532 байтам, а зашифрованные данные
  физически занимают 544 байта после выравнивания AES-CBC.

### Исправлено

- **Отмена действительно останавливает сборку.** Кнопка **«Отменить»**
  завершает всё дерево процессов на macOS и Windows: worker, extractor и
  MkPFS. Очередь остальных выбранных игр очищается, а дочерние процессы больше
  не продолжают запись в фоне.
- **Полный последний блок AES-CBC.** Для зашифрованных NP-записей
  `0x400`–`0x403` extractor теперь округляет хранимый ciphertext до
  16-байтной границы, читает и расшифровывает полный блок, а затем записывает
  только объявленный размер plaintext.
- **Исправлен `npbind.dat`.** Для примера 532/544 в итоговый файл попадают ровно
  532 корректных байта, включая неповреждённый внутренний 20-байтный SHA-1
  footer. Старая логика обрывала ciphertext и могла повредить последние байты
  этого footer.
- **Устаревший кэш не переиспользуется.** Ревизия extractor изменена, поэтому
  временные деревья, созданные старой логикой, автоматически признаются
  устаревшими и извлекаются заново. Корректное состояние 0.2.6 по-прежнему
  пригодно для быстрого продолжения после отмены или ошибки.
- **Однозначные настройки формата.** Уровень и число потоков сжатия относятся
  только к FFPFSC; для raw exFAT сжатие не запускается.
- **Строгая выборочная проверка.** Обязательные файлы извлекаются из готового
  образа и побайтово сравниваются с объединённым источником. Standalone
  `verify` распознаёт raw exFAT по сигнатуре и проверяет внутренний SHA-1
  `npbind.dat`, если файл присутствует.
- **Раздельные sidecar-файлы.** Имена manifest и ShadowMount-инструкции теперь
  сохраняют `.ffpfsc` или `.exfat`, поэтому два формата одной версии игры не
  перезаписывают метаданные друг друга.

### Проверено

- Согласованность версии приложения, macOS bundle, Windows metadata, имён
  архивов и release notes.
- Python-тесты CLI, GUI, pipeline, выбора формата и управления числом потоков.
- Тесты отмены и завершения дерева процессов для macOS и Windows.
- Нативные C++-тесты extractor, включая синтетический случай
  `532 bytes plaintext ← 544 bytes ciphertext`.
- Создание и выборочная проверка обоих форматов без дополнительной полной копии
  raw exFAT.
- Smoke-тесты самодостаточных macOS arm64 и Windows x64 приложений и проверка
  архитектуры включённых бинарников.

Важно: 0.2.6 исправляет создание образов, извлечение метаданных и управление
процессами приложения. Этот выпуск не модифицирует ShadowMountPlus и не заявляет
об исправлении регистрации Trophy или других проблем runtime на PS5.

## English version

### Added

- **Output format selection.** Compressed `.ffpfsc` remains the default, with
  an uncompressed raw `.exfat` option now available.
- **Direct exFAT creation.** The uncompressed image is created as the single
  partial file, then atomically published under its final name after
  verification. Verification selectively reads the filesystem structure,
  required game files, and metadata, so it does not create a second full-size
  image.
- **Selectable MkPFS workers.** FFPFSC compression can use from 1 worker up to
  the system's logical CPU count. The default is half of the logical CPUs, with
  a minimum of one, leaving resources available during long builds.
- **NP-metadata regression coverage.** A native test reproduces the case where
  `npbind.dat` declares 532 bytes while its encrypted storage occupies 544
  bytes after AES-CBC alignment.

### Fixed

- **Cancellation now stops the actual build.** **Cancel** terminates the full
  process tree on macOS and Windows: the worker, extractor, and MkPFS. It also
  clears the remaining game queue, so detached children no longer continue
  writing in the background.
- **Complete final AES-CBC block.** For encrypted NP entries
  `0x400`–`0x403`, the extractor now rounds stored ciphertext to the 16-byte
  boundary, reads and decrypts the complete block, then writes only the
  declared plaintext size.
- **Correct `npbind.dat`.** In the 532/544 example, exactly 532 valid bytes are
  written, including the intact internal 20-byte SHA-1 footer. The old logic
  truncated ciphertext and could corrupt the footer's final bytes.
- **Stale cache is not reused.** The extractor revision changed, so temporary
  trees produced by the old logic are automatically treated as stale and
  extracted again. Correct 0.2.6 state remains reusable for fast recovery after
  cancellation or failure.
- **Unambiguous format controls.** Compression level and worker count apply
  only to FFPFSC; raw exFAT does not start a compression stage.
- **Strict selective verification.** Required files are extracted from the
  finished image and compared byte-for-byte with the merged source. Standalone
  `verify` recognizes raw exFAT by signature and validates the internal
  `npbind.dat` SHA-1 whenever that file is present.
- **Format-specific sidecars.** Manifest and ShadowMount instruction names now
  retain `.ffpfsc` or `.exfat`, so the two formats for the same game version
  cannot overwrite each other's metadata.

### Verified

- Consistent application version, macOS bundle, Windows metadata, archive
  names, and release notes.
- Python coverage for the CLI, GUI, pipeline, output selection, and worker
  configuration.
- Cancellation and process-tree termination tests for macOS and Windows.
- Native extractor C++ tests, including the synthetic
  `532 bytes plaintext ← 544 bytes ciphertext` case.
- Creation and selective verification of both output formats without an
  additional full-size raw exFAT copy.
- Self-contained macOS arm64 and Windows x64 smoke tests and bundled-binary
  architecture audits.

Important: 0.2.6 corrects image creation, metadata extraction, and application
process management. It does not modify ShadowMountPlus and does not claim to
fix Trophy registration or other PS5 runtime behavior.
