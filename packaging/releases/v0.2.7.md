# PS4 FFPFSC 0.2.7

> Распакованные игры, backport-слои, корректный `param.json`, Unicode-пути
> Windows и безопасный выбор источников.
>
> Unpacked-game input, backport layers, correct `param.json`, Windows Unicode
> paths, and safe source selection.

## Загрузки / Downloads

- `PS4-FFPFSC-v0.2.7-macos-arm64.zip` — macOS 13+, Apple Silicon.
- `PS4-FFPFSC-v0.2.7-windows-x64.zip` — Windows 10/11 x64.

## Русская версия

### Добавлено

- **Сборка из распакованной игры.** Можно выбрать плоский каталог с
  `eboot.bin` и `sce_sys/param.sfo` либо контейнер дампера с `app/`,
  необязательными `patch/` и `addcont/`. Исходное дерево используется только
  для чтения и после сборки остаётся на месте без изменений.
- **Поддержка backport-слоёв.** Patch с явным маркером `backport`,
  `back-port` или `Fix<версия прошивки>` применяется после обычного update с
  тем же `APP_VER`. Точный порядок сохраняется в inventory, manifest и отчёте
  объединения.
- **Дополнительные параметры `param.json`.** Ненулевые
  `USER_DEFINED_PARAM_1…4` из итогового `param.sfo` зеркалируются как
  `userDefinedParam1…4`. Это учитывает игры наподобие Sekiro, где параметр
  влияет на язык при запуске из образа.
- **Отдельные DLC-образы в режиме `auto`.** Обнаруженные DLC не теряются после
  staging, а публикуются как отдельные проверенные артефакты с entitlement
  label в manifest.

### Исправлено

- **`param.sfo` больше не переписывается.** Итоговый файл остаётся байтовой
  копией последнего overlay, включая `CATEGORY=gp`, `APP_VER`, локализацию и
  пользовательские параметры. Заголовок для `param.json` при отсутствии
  основного `TITLE` выбирается начиная с `TITLE_01`.
- **Unicode-пути Windows.** Нативный extractor принимает широкие аргументы и
  переводит пути в UTF-8 для JSON. Имена с `™`, кириллицей и другими
  не-ASCII-символами поддерживаются как снаружи PKG, так и внутри него.
- **Выбор PKG в GUI.** Неподдерживаемый неотмеченный файл больше не блокирует
  поддерживаемую игру. При двух неоднозначных update одной версии можно снять
  лишний patch и собрать выбранный непротиворечивый набор.
- **Ошибочные метаданные не завершают сканирование.** Пустой или некорректный
  `APP_VER` отображается как причина блокировки конкретной игры вместо
  необработанного исключения.
- **Точные источники CLI.** Команды `unpack` и `merge` пересканируют переданные
  `--pkg-file`/`--pkg-dir`/`--dump-dir`, а не используют инвентарь от другого
  предыдущего запуска. `list` показывает фактический порядок наложения patch.
- **Надёжное продолжение для распакованного дерева.** Повторное использование
  разрешается только при полном совпадении tree signature; любое изменение
  файла требует нового merge.
- **Защита исходного дерева.** Приложение заранее отклоняет опасное пересечение
  распакованного источника с временной рабочей областью или папкой результата.
  В dump-режиме дочерние строки являются информационными: выбирается весь
  контейнер, поэтому GUI больше не показывает неработающие галочки.
- **Атомарная публикация набора с DLC.** Ошибка подготовки любого DLC не
  оставляет основной образ или частичный набор новых артефактов, блокирующий
  повторную сборку.
- **Сборка приложения на macOS 26.** Полная ICNS-иконка теперь формируется
  внутри проекта без неработающего преобразования `iconutil`, поэтому
  релизная сборка остаётся воспроизводимой на актуальной macOS.

### Проверено

- Полный Python-набор тестов CLI, GUI, inventory, merge, resume, очистки,
  Unicode и всех трёх режимов источника.
- Нативные C++-тесты extractor, включая AES-CBC 544→532 и Unicode-пути.
- Реальный набор Overcooked 2: base, обычный update 1.10 и `Fix5.05` получают
  порядок `base → update → backport` без конфликта одинаковой версии.
- Реальное распакованное дерево CUSA02172 распознаётся без изменения исходных
  файлов.
- Самодостаточные архивы macOS arm64 и Windows x64 проходят встроенные smoke,
  архитектурный аудит и проверку контрольных сумм.

Важно: отдельные DLC-артефакты корректно создаются конвертером, но их
регистрация и подключение во время запуска зависят от поддержки среды
монтирования. Версия 0.2.7 не заявляет об исправлении Trophy или других
runtime-проблем PS5.

## English version

### Added

- **Build from an unpacked game.** Select either a flat root containing
  `eboot.bin` and `sce_sys/param.sfo`, or a dumper container with `app/` and
  optional `patch/` and `addcont/` directories. The source tree is read-only
  and remains unchanged after the build.
- **Backport-layer support.** A patch explicitly named with `backport`,
  `back-port`, or `Fix<firmware version>` is applied after the ordinary update
  with the same `APP_VER`. The exact order is recorded in the inventory,
  manifest, and merge report.
- **Additional `param.json` parameters.** Non-zero
  `USER_DEFINED_PARAM_1…4` values from the final `param.sfo` are mirrored as
  `userDefinedParam1…4`. This covers games such as Sekiro where the value
  affects language selection when launched from an image.
- **Separate DLC images in `auto` mode.** Detected DLC is no longer discarded
  after staging; it is emitted as a separate verified artifact with its
  entitlement label recorded in the manifest.

### Fixed

- **`param.sfo` is no longer rewritten.** The result remains a byte-for-byte
  copy of the final overlay, including `CATEGORY=gp`, `APP_VER`, localization,
  and user parameters. When the primary `TITLE` is absent, `TITLE_01` is the
  first fallback used for `param.json`.
- **Windows Unicode paths.** The native extractor accepts wide arguments and
  serializes paths as UTF-8 for JSON. Names containing `™`, Cyrillic, and other
  non-ASCII characters work both outside the PKG and in its internal paths.
- **GUI source selection.** An unchecked rejected file no longer blocks a
  supported game. When two ambiguous updates share a version, the unwanted
  patch can be unchecked and the remaining valid subset can be built.
- **Invalid metadata no longer aborts scanning.** An empty or malformed
  `APP_VER` blocks only the affected game and is shown as a reason instead of
  raising an uncaught exception.
- **Exact CLI sources.** `unpack` and `merge` rescan the supplied
  `--pkg-file`/`--pkg-dir`/`--dump-dir` inputs instead of reusing an inventory
  from a different earlier run. `list` reports the actual patch order.
- **Reliable unpacked-tree resume.** Reuse requires an exact tree-signature
  match; changing any source file forces a new merge.
- **Source-tree boundary protection.** Unsafe overlap with the temporary
  workspace or output directory is rejected before any work starts. In dump
  mode, component rows are informational and the whole container is selected,
  so the GUI no longer presents controls that do not affect the build.
- **Atomic publication with DLC.** A failure while preparing any DLC leaves no
  newly published main image or partial artifact set that could block a retry.
- **Application packaging on macOS 26.** The complete ICNS is now generated
  by the project without the failing `iconutil` conversion, keeping release
  builds reproducible on current macOS.

### Verified

- Complete Python coverage for the CLI, GUI, inventory, merge, resume,
  cleanup, Unicode, and all three source modes.
- Native extractor C++ tests, including AES-CBC 544→532 and Unicode paths.
- A real Overcooked 2 base, ordinary 1.10 update, and `Fix5.05` set receives
  the deterministic `base → update → backport` order without a same-version
  conflict.
- A real unpacked CUSA02172 tree is recognized without modifying its files.
- Self-contained macOS arm64 and Windows x64 archives pass their bundled
  smoke tests, architecture audits, and checksum verification.

Important: the converter now creates separate DLC artifacts correctly, but
their runtime registration and mounting depend on support in the mounting
environment. Version 0.2.7 does not claim to fix Trophy registration or other
PS5 runtime issues.
