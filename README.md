# ps4ffpsc

**Языки / Languages:** **Русский** · [English](README_EN.md)

Самодостаточный GUI-конвертер поддерживаемых PS4 PKG в проверенные
FFPFSC-образы для ShadowMountPlus. Готовые версии для macOS arm64 и Windows x64
не требуют Python или внешних приложений.

Инструмент обрабатывает только законно полученные PKG, которые уже поддерживает
приложенный shadPS4 0.7.0. Он не ищет ключи, не обходит DRM, не скачивает игры и
не преобразует неподдерживаемый retail PKG. Такой вход получает статус
`unsupported_or_encrypted_pkg`, после чего обработка остальных файлов продолжается.

## GUI-приложение

Оба архива Release самодостаточны: Python, Qt, MkPFS и нативный модуль PKG уже
включены.

- **Windows x64:** полностью распакуйте
  `PS4-FFPFSC-v0.2.2-windows-x64.zip` и запустите `PS4 FFPFSC.exe`. Остальные
  файлы должны оставаться рядом с программой. Поскольку сборка не подписана
  коммерческим сертификатом, при первом запуске Microsoft Defender SmartScreen
  может потребовать явного разрешения.
- **macOS arm64:** распакуйте `PS4-FFPFSC-v0.2.2-macos-arm64.zip`, перенесите
  `PS4 FFPFSC.app` в `/Applications` и откройте. Текущий Release подписан
  ad-hoc, поэтому при первом запуске используйте
  **Control-клик → Открыть**.

Чтобы самостоятельно собрать такой же самодостаточный Release для macOS:

```bash
./scripts/bootstrap_macos.sh
./scripts/build_release_macos_arm64.sh
open "build-release/dist/PS4 FFPFSC.app"
```

ZIP, SHA-256 и заметки выпуска появятся в `release/`. Для разработки GUI можно
запустить через `./ps4ffpsc-gui.command`. В окне:

1. Нажмите **«Выбрать PKG-файлы…»** для отдельных base/patch/DLC или
   **«Выбрать папку…»** — тогда `.pkg`/`.PKG` будут найдены во всех подпапках.
   Язык всего интерфейса переключается через **Русский / English** в верхней
   части окна; выбор сохраняется между запусками.
2. Выберите отдельную папку, куда сохранить готовые `.ffpfsc` и sidecar-файлы.
   Для временных файлов по умолчанию используется системный временный каталог
   (`%TEMP%` в Windows или `/tmp` в macOS); при необходимости укажите другой
   диск или каталог прямо в окне. Распакованные PKG, рабочее дерево и MkPFS tmp
   сохраняются только внутри `PS4 FFPFSC` в выбранном временном каталоге, а не
   в `Application Support`.
3. Нажмите **«Сканировать»**, проверьте сгруппированные игры и отметьте нужные.
4. Нажмите **«Собрать выбранные»**. Окно показывает общий процент, текущий
   подэтап, прошедшее время и расчётное оставшееся время. Операцию можно
   отменить и позднее продолжить.

Для ускорения объединения приложение использует hardlinks внутри выбранного
временного тома и автоматически переходит к обычному копированию, если файловая
система их не поддерживает. После проверенного объединения распакованные копии
PKG удаляются, а после полностью успешной сборки удаляется весь временный каталог
этой игры. При ошибке или отмене проверенное рабочее состояние сохраняется для
продолжения. Исходные PKG и готовые файлы очистка не затрагивает.

Исходные PKG GUI не перемещает и не изменяет. Настройка
**«Пересобрать существующее»** нужна только для осознанной замены уже
существующих результатов и промежуточных деревьев.

Windows x64-архив воспроизводимо собирается и тестируется на нативном Windows
runner через `.github/workflows/build-windows-x64.yml`. Скрипт
`scripts/build_release_windows_x64.ps1` проверяет GUI, worker, MkPFS, модуль
чтения PKG и x64-архитектуру всех включённых EXE/DLL/PYD.

Сканирование читает только заголовки и метаданные PKG: оно не копирует пакет и
не вычисляет SHA-256 всего многогигабайтного файла. Полная контрольная сумма
считается только после нажатия сборки, перед извлечением. Если в группе есть
только patch (`CATEGORY=gp`) и DLC, кнопка меняется на
**«Проверить готовность»** и объясняет, что требуется базовый PKG
(`CATEGORY=gd`).

## Пошаговый сценарий на macOS ARM64

1. Скопируйте base, patch и DLC с расширением `.pkg`/`.PKG` в `pkg/`.
2. Один раз выполните `./scripts/bootstrap_macos.sh` и `./scripts/build_macos.sh`.
3. Проверьте среду: `./ps4ffpsc doctor`.
4. Просканируйте метаданные: `./ps4ffpsc scan`.
5. Просмотрите группы и конфликты: `./ps4ffpsc list`.
6. Соберите всё однозначное:
   `./ps4ffpsc build --all --compat current-smp --include-dlc auto`.
7. Найдите `.ffpfsc`, `.sha256`, `.manifest.json` и `.shadowmount.txt` в `output/`.
8. Скопируйте `.ffpfsc` на USB, например в `/mnt/usb0/ps4ffpsc/`.
9. Добавьте этот путь через `scanpath=` или строку полного пути к образу в
   `/data/shadowmount/manual.lst`.
10. После сканирования проверьте `/data/shadowmount/debug.log`.

`static_shadowmount_compatible=true` означает, что layout и metadata проходят
проверки по исходникам ShadowMountPlus. Для новых образов
`ps5_runtime_verified` остаётся `false`, пока пользователь не проверит конкретный
артефакт на консоли. Созданный здесь Journey v01.01 пользователь успешно
запустил и проверил на PS5 26 июля 2026 года.

## Почему pipeline устроен так

- PKG нельзя просто переименовать в FFPSC: это разные контейнеры и файловые системы.
- Внешний compressed PFS должен содержать вложенный образ exFAT; прямые игровые
  файлы в корне FFPSC ShadowMountPlus игнорирует.
- Немодифицированный ShadowMountPlus ищет `sce_sys/param.json`, поэтому режим
  `current-smp` генерирует JSON, но всегда сохраняет оригинальный `param.sfo`.
- Патчи сортируются как последовательности целых компонентов, а затем накладываются
  поверх base. `01.09 < 01.10 < 01.100`; float не используется.
- DLC — отдельный additional content с entitlement/mount/registration semantics.
  Он подготавливается отдельно во время сборки; временный staging удаляется
  после успеха, а runtime-поддержка честно не заявляется.
- PFSC использует zlib; документация ShadowMountPlus предупреждает о примерно
  `150–250 MB/s`, поэтому streaming-heavy игры могут работать хуже.
- После прерывания повторите команду с `--resume`: проверенное рабочее дерево
  сверяется по SHA-256 и по возможности используется без повторного извлечения.

Состояние: `./ps4ffpsc status`. Удаление только временного `work/`:
`./ps4ffpsc clean --work`.
