## Входные данные экспериментальной сборки DLC

NativeAOT-helper DLC требует **.NET SDK 8** и фиксирует
`Microsoft.NETCore.App.Runtime` на версии **8.0.26**. Шаблон его модуля должен
быть собран на macOS или Linux закреплённым OpenOrbis PS4 Toolchain **v0.5.4**;
сценарий загрузки проверяет SHA-256 архива
`3c7cd5bb593ca74fa1c13fd59f3938dc0fc07985167f7275063019e63abe4526`.

Сборка macOS arm64 закреплена на официальном установщике **Python 3.13.14**,
PySide6 Essentials/shiboken6 **6.9.3** и Crypto++ **8.9.0**, собираемой из
исходников. Bootstrap проверяет SHA-256 пакета Python
`8e58affb218c155a1dfdc27b291f817129669f8760e7a297adb2e4439ba5d2e8`.
Framework извлекается в изолированный build-cache без записи в `/Library` и
без прав администратора.
Сценарий подготовки Crypto++ проверяет SHA-256
`4cc0ccc324625b80b695fcd3dee63a66f1a460d3e51b71640cdbfc4cd1a3779c`,
после чего собирает каждый объект arm64 для macOS 13.0 вместо использования
локальной Homebrew-сборки. Финальный аудит приложения отклоняет любой Mach-O
не arm64, внешнюю несистемную зависимость, отсутствующую минимальную версию
системы или требование macOS выше 13.0.

Для ручной релизной сборки на нативной Windows x64 используйте Python 3.13.14,
.NET SDK 8, CMake/Ninja и статические зависимости vcpkg. Перед запуском
`scripts/build_release_windows_x64.ps1` задайте `PS4FFPSC_DLC_TEMPLATE` с
абсолютным путём к шаблону, подготовленному на macOS или Linux. GitHub Actions
выполняет эти две платформенные стадии автоматически.

Запустите:

```bash
./scripts/build_macos.sh
.venv/bin/pytest -q
./ps4ffpsc doctor
./ps4ffpsc scan
./ps4ffpsc build --all --compat current-smp --dlc-mode off
./ps4ffpsc verify output/<artifact>.ffpfsc
```

Обычная проверка релиза оставляет экспериментальный режим DLC выключенным.
Отдельный тест DLC в едином образе должен явно включить его через
`--dlc-mode single-experimental`, использовать только одноразовые пути
промежуточных и
выходных данных, а после завершения подтвердить, что метаданные и размеры
исходных PKG не изменились.

Набор использует только синтетические фикстуры SFO и каталогов. Он охватывает
повреждённый SFO, helpers классификации, порядок версий, ID и метки содержимого,
Unicode, обход путей, символические ссылки, дубликаты, конфликтующие base,
потерянные patch, отчёты наложения, детерминированный JSON, разреженные файлы
больше 4 ГиБ, продолжение по stat-метаданным и настоящую интеграцию MkPFS со
вложенным exFAT.

Регрессионные тесты версии 0.2.8 отдельно проверяют границу исправления
`npbind.dat`. Для выбранной распакованной игры неверный 20-байтовый SHA-1-футер
исправляется только во временной объединённой копии; байты до футера и исходный
файл остаются точными копиями прежних значений. Файл с неправильной структурой
отклоняется без записи. Тесты DLC различают `PSAC` с данными и `PSAL` только с
лицензией, проверяют согласованность заголовка PKG и `license.dat` и сохраняют
`runtime_verified=false` без аппаратного результата.

Проверка релиза на Apple Silicon требует успешного прохождения CMake/CTest,
полного набора pytest и smoke-теста замороженного GUI. Регрессионные тесты
явно завершаются ошибкой, если обычный код scan, unpack, resume или build
пытается вызвать helper SHA-256 для полного файла. Ранее созданный артефакт
Journey прошёл проверку внешнего контейнера MkPFS без ошибок и точное сравнение
SHA после глубокого извлечения:
`host_tests_passed=true`,
`static_shadowmount_checks_passed=true`. Пользователь подтвердил, что именно
этот артефакт Journey запускается и работает на PS5 2026-07-26, поэтому его
сопутствующий файл и локальные отчёты содержат
`ps5_runtime_verified=true`. Новые артефакты по умолчанию остаются
непроверенными до испытания на консоли.

Замороженное приложение arm64 дополнительно проходит аудит нативной
архитектуры и зависимостей, doctor, проверку встроенного MkPFS, offscreen
smoke-тест запуска Qt, синтетическую многопроцессную упаковку и проверку
FFPFSC, а также точную проверку испытанного на консоли образа Journey.

Предоставленный каталог Beat Saber также сканировался замороженным рабочим
процессом: 247 PKG (4,9 ГБ) классифицировались за 3,6–11 секунд при прогретых и
холодных запусках без полного чтения файлов для SHA-256. В списке корректно
показаны один patch и 246 DLC, но нет base-пакета с `CATEGORY=gd`, поэтому
готовность блокируется с явным объяснением в интерфейсе, а не неактивной
кнопкой.

Base PKG Beat Saber размером 243 МиБ извлекался helper версии v0.2.2 и
оптимизированным helper на одном Mac с Apple Silicon. Диагностика показала, что
главным узким местом холодного кэша были случайные операции чтения по 64 КиБ
через SMB, поэтому теперь helper сочетает постоянный дескриптор с ограниченным
кэшем упреждающего чтения 8 МиБ. Полные файловые manifest с SHA-256 от старого
и нового helper совпали: 138 файлов, 306 326 961 байт. Настоящая сквозная
сборка завершила извлечение, объединение, упаковку FFPFSC, проверку контейнера
и очистку временной рабочей области за 20,6 секунды на тестовом Mac. Поток
байтов прогресса сообщил ожидаемый объём распакованных данных без рекурсивного
обхода выходного каталога.

Для эксперимента версии 0.2.8 с DLC в едином образе полный набор Beat Saber
CUSA12878 снова инвентаризирован при наличии base и patch. Из 246 DLC PKG один
побайтово идентичный дубликат исключён, использовано 245 уникальных записей
прав доступа. Полученный на компьютере FFPFSC прошёл проверку MkPFS, глубокое
извлечение и точное сравнение всех 2 032 файлов и 277 каталогов с
подготовленным деревом. Эти проверки подтверждают создание и целостность
контейнера, но не runtime-поведение PS5. Возможность остаётся отключённой по
умолчанию и документируется как экспериментальная, пока аппаратные тесты для
каждой игры не подтвердят обнаружение и использование DLC.
