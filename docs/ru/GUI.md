# Графический интерфейс

**Языки:** [English](../GUI.md) · **Русский** ·
[Содержание](README.md)

`PS4 FFPFSC` — автономное приложение для macOS arm64 и Windows x64,
реализованное с помощью PySide6 Essentials. В него встроены Python, Qt, MkPFS
и нативный helper PKG, но оно вызывает тот же рабочий процесс `ps4ffpsc`,
который используется автоматическими тестами. Поэтому у графического
интерфейса и командной строки нет разных реализаций преобразования.

## Режимы ввода

- **Выбранные файлы** явно передаёт каждый выбранный `.pkg`/`.PKG`. Каталог
  `pkg/` по умолчанию не подмешивается в этот режим.
- **Папка рекурсивно** сканирует выбранный каталог и все вложенные каталоги.
  Файлы с другими расширениями игнорируются.
- **Распакованная игра** принимает либо плоский корень с `eboot.bin` и
  `sce_sys/param.sfo`, либо корень в стиле dumper с `app/` и необязательным
  `patch/`. Источник остаётся доступным только для чтения; объединение никогда
  не забирает его файлы.

При смене режима прежний список найденного очищается. Исходные PKG остаются на
месте и открываются extractor только для чтения.

Переключатель языка в заголовке полностью переводит интерфейс между русским и
английским без перезапуска приложения. Выбор сохраняется для следующего
запуска.

При сканировании намеренно не читается каждый байт каждого пакета. Программа
читает заголовки и метаданные пакетов и сохраняет недорогой идентификатор из
пути, размера и времени изменения. Перед сборкой рабочий процесс обновляет
этот идентификатор и сразу начинает извлечение; предварительного полного
хеширования исходного файла нет.

## Порядок работы

1. Выберите файлы PKG, папку с рекурсивным поиском PKG или дерево
   распакованной игры.
2. Выберите папку результата.
3. Оставьте системный временный каталог (`%TEMP%` в Windows или `/tmp` в
   macOS) либо выберите другой каталог или том. Интерфейс показывает текущее
   свободное место и запоминает выбор.
4. Запустите сканирование. Дерево группирует пакеты BASE, PATCH и DLC по
   TITLE_ID и показывает конфликты или неподдерживаемые пакеты, не выбирая их
   для сборки. Отдельный столбец размера показывает каждый PKG и приблизительный
   суммарный размер источников игры, а сводка — общий размер отмеченных
   пакетов.
5. Оставьте или снимите отметку у каждого PKG. По умолчанию отмечены все
   поддерживаемые пакеты. Точные копии, найденные по встроенному digest пакета,
   показаны как дубликаты и по умолчанию не отмечены; разделённые пакеты
   `part1`/`part2` с разными digest остаются отмеченными. Неподдерживаемые
   элементы выводятся отдельно и не блокируют отмеченную поддерживаемую игру.
   Явно обозначенный `backport`, `back-port` или `Fix5.05` показывается как
   слой backport и накладывается после обычного обновления с той же APP_VER.
   В режиме распакованной игры строка верхнего уровня выбирает весь исходный
   контейнер; дочерние строки TREE/PATCH TREE/DLC информационные, поскольку
   эти части нельзя независимо исключить, не изменив выбранную структуру
   источника.
6. Выберите формат и запустите сборку. Сжатый `FFPFSC` используется по
   умолчанию; доступен также несжатый raw `exFAT`. Raw exFAT записывается
   непосредственно в итоговый артефакт, а выборочная проверка читает структуру
   файловой системы и побайтово сравнивает только обязательные игровые файлы,
   не создавая второй полноразмерный образ.
7. Для FFPFSC выберите уровень сжатия от 0 до 9 и число рабочих потоков от 1
   до обнаруженного числа логических CPU. По умолчанию задан уровень 7;
   уровень 0 отключает deflate внутри контейнера FFPFSC. По умолчанию
   используется половина логических CPU, но не меньше одного потока, поэтому
   преобразование не занимает все доступные потоки. Оба значения сохраняются.
   Настройки сжатия не применяются к raw exFAT.
8. Экспериментальный режим DLC в едином образе отключён по умолчанию.
   Включайте его только для осознанной проверки совместимости. `PSAC` — это
   DLC с данными, `PSAL` — DLC только с лицензией. Режим может изменить
   временные копии исполняемых файлов игры и поместить выбранные
   вспомогательные данные DLC в основной образ; исходные PKG и выбранное
   распакованное дерево не меняются. Завершённый и проверенный образ не
   доказывает, что DLC будут зарегистрированы, обнаружены или доступны на PS5.
   До аппаратной проверки сохраняется `runtime_verified=false`.

Если пакеты найдены, но ни одну игру нельзя собрать, основная кнопка остаётся
доступной как **Проверить готовность** / **Check readiness**. Она перечисляет
фактические причины блокировки. В частности, большой patch с `CATEGORY=gp`
остаётся обновлением; для сборки с DLC необходим base с `CATEGORY=gd`.

Область прогресса показывает общий процент для всех выбранных игр, текущий
этап и подэтап, точное прошедшее время и оценку оставшегося времени. Во время
извлечения нативный helper передаёт фактическое число записанных байтов прямо
из цикла расшифровки и записи. Доля извлечения каждого пакета взвешивается по
размеру исходного PKG, поэтому маленький base и большой patch больше не
получают одинаковый вес. ETA извлечения рассчитывается по этой скорости
байтов. Сжатие и проверка MkPFS продолжают передавать собственный
структурированный прогресс. Пока выполнено недостаточно работы для полезной
оценки, поле оставшегося времени прямо сообщает, что расчёт ещё выполняется.
Игры собираются по одному TITLE_ID, а при ошибке одной сборки интерфейс
переходит к следующей выбранной игре.

Кнопка **Отмена** очищает оставшуюся очередь игр и завершает всё дерево
процессов в macOS и Windows: не только рабочий процесс интерфейса, но также
нативный extractor PKG и MkPFS. Поэтому после отмены не остаются отдельные
дочерние процессы, продолжающие запись. Следующий запуск может повторно
использовать проверенное состояние извлечения, если включено
**Продолжить прерванную работу**.

Перед извлечением режим продолжения проверяет только метаданные каждого ранее
завершённого дерева пакета: относительные пути, размеры и время изменения.
Совпавшие деревья используются повторно без открытия файлов с содержимым;
извлекаются только отсутствующие, изменившиеся или ранее не обработанные PKG.
Состояние каждого пакета сохраняется после успешного извлечения и также может
быть восстановлено из текущего manifest.

Ревизия extractor входит в идентификатор продолжения. Версия 0.2.6 повышает
эту ревизию, поэтому деревья, созданные старой логикой извлечения NP-метаданных,
считаются устаревшими и извлекаются заново, а не принимаются как корректный
кэш.

При объединении жёсткие ссылки в пределах одной файловой системы
предпочтительнее полных копий; на файловых системах без их поддержки
автоматически используется копирование. Извлечённые деревья пакетов удаляются
после проверки объединённого дерева. Успешная сборка удаляет всю временную
рабочую область игры; неудачная или отменённая сохраняет проверенное состояние,
необходимое для продолжения. Ни один путь очистки не меняет исходные PKG или
готовые выходные артефакты. Для распакованного источника используется та же
политика жёстких ссылок и копирования с отключённым изъятием исходных файлов,
а очистка остаётся ограничена временной рабочей областью.

Helper PKG держит один дескриптор чтения открытым на протяжении всего
извлечения и использует ограниченный кэш упреждающего чтения 8 МиБ вместо
тысяч мелких операций по 64 КиБ. Это снижает накладные расходы SMB/NAS,
особенно в macOS. Прогресс передаётся с ограниченной частотой и не измеряет
временный каталог рекурсивно, поэтому индикатор не вызывает дополнительного
чтения или копирования игровых данных.

Зашифрованным NP-записям `0x400`–`0x403` нужны два размера: объявленный размер
открытых данных и сохранённый размер шифротекста, округлённый вверх до
16-байтовой границы AES-CBC. В регрессионном случае объявленный размер
`npbind.dat` равен 532 байтам, но в PKG он занимает 544 байта. Теперь helper
читает и расшифровывает все 544 байта, а записывает ровно 532 байта. Благодаря
этому внутренний 20-байтовый SHA-1-футер сохраняется, а не повреждается в
последних байтах.

Отдельно для **выбранной распакованной игры** версия 0.2.8 автоматически
проверяет `sce_sys/npbind.dat` после копирования или создания ссылок во
временное дерево `merged`. Если корректны magic, версия, объявленный размер и
структура записей, но не совпадает только SHA-1-футер, программа атомарно
заменяет исключительно последние 20 байтов во временной копии. При корректном
футере запись не выполняется; при ошибочной структуре сборка завершается
ошибкой вместо попытки скрыть повреждение. Выбранное исходное дерево во всех
случаях остаётся неизменным.

## Запуск и выпуск автономных приложений

Скачайте и полностью распакуйте
`PS4-FFPFSC-v0.2.8-windows-x64.zip`, затем запустите `PS4 FFPFSC.exe`.
Сопутствующий каталог `_internal` и `ps4ffpsc-worker.exe` — обязательные части
автономного приложения.

Для сборки Windows-архива на компьютере с нативной Windows x64 установите
Python 3.13.14, .NET SDK 8, CMake/Ninja и необходимые статические пакеты vcpkg.
Сначала соберите шаблон модуля DLC на macOS или Linux с OpenOrbis PS4
Toolchain v0.5.4, затем укажите абсолютный путь к нему:

```powershell
$env:PS4FFPSC_DLC_TEMPLATE = "C:\path\to\dlcldr.prx"
.\scripts\build_release_windows_x64.ps1
```

Workflow GitHub Actions `.github/workflows/build-windows-x64.yml` устанавливает
подготовленный в Linux шаблон и остальные зависимости Windows, запускает набор
тестов, собирает приложение, проверяет архитектуру x64 всех включённых
PE-файлов и загружает ZIP, контрольную сумму и описание релиза как артефакт.

NativeAOT-helper работает с .NET 8 и фиксирует
`Microsoft.NETCore.App.Runtime` 8.0.26.

Для macOS arm64:

```bash
./scripts/bootstrap_macos.sh
./scripts/build_release_macos_arm64.sh
open "build-release/dist/PS4 FFPFSC.app"
```

Bootstrap загружает официальный пакет Python 3.13.14 для macOS, проверяет его
закреплённую SHA-256 и извлекает framework в изолированный build-cache, не
изменяя `/Library`. В виртуальное окружение проекта устанавливаются PySide6
Essentials и shiboken6 6.9.3. Crypto++ 8.9.0 загружается как закреплённый архив
исходников upstream и собирается локально для arm64 с минимальной macOS 13.0;
готовая библиотека Homebrew намеренно не используется.

Сценарий выпуска собирает helper с этой статической Crypto++, замораживает
runtime Python и Qt, подписывает приложение и проверяет архитектуру, зависимости
и deployment target каждого Mach-O. Если хотя бы один компонент требует macOS
выше 13.0, выпуск останавливается. Затем выполняются smoke-тесты замороженных
doctor, MkPFS и GUI и создаются ZIP и файл SHA-256 в каталоге `release/`.

Сценарий выпуска использует ad-hoc-подпись, если
`PS4FFPSC_CODESIGN_IDENTITY` не содержит установленного сертификата
Developer ID. Для публичного ZIP с ad-hoc-подписью обычно требуется один раз
выбрать **Control-клик → Открыть**. Для разработки из дерева исходников
используйте `./ps4ffpsc-gui.command`.
