# Архитектура

**Языки:** [English](../ARCHITECTURE.md) · **Русский** ·
[Содержание](README.md)

`ps4_pkg_extract` — узкая C++-граница вокруг поставляемого вместе с проектом и
прошедшего аудит подмножества исходников PKG из shadPS4 0.7.0. Команда
`inspect --fast` проверяет границы таблиц PKG/SFO, вызывает `PKG::Open` и
`PSF::Open` и выводит один JSON-объект, не хешируя файл целиком. Команда
`extract` вызывает `PKG::Extract`/`ExtractFiles` и помещает результат в
выделенное дерево `.partial`. Автономный extractor держит один дескриптор
чтения PKG открытым на протяжении всей последовательной операции и использует
ограниченный 8 МиБ кэш упреждающего чтения. Поэтому PKG на SMB/NAS не
запрашивается тысячами мелких операций по 64 КиБ. После успешной записи
выходных данных extractor передаёт счётчики байтов с ограниченной частотой.

Уровень Python `ps4ffpsc` определяет правила обработки. Он принимает либо PKG,
либо распакованный источник, доступный только для чтения. Плоский распакованный
источник считается уже объединённым приложением; контейнер в стиле dumper
предоставляет `app/` как базу и необязательный `patch/` как накладываемый слой.

1. Рекурсивно найти расширения `.pkg` без учёта регистра либо проверить
   выбранное распакованное дерево (`eboot.bin` и `sce_sys/param.sfo`).
2. Классифицировать base и patch по `CATEGORY` из SFO и patch-флагам
   заголовка. Для DLC PKG использовать тип содержимого `PSAC`/`PSAL` из
   заголовка пакета; `CATEGORY=ac`/`al` из SFO служит только запасным
   вариантом для распакованных деревьев addcont.
3. Сгруппировать их по проверенному `CUSA` TITLE_ID; обнаружить конфликты,
   потерянные обновления и несовпадения регионов.
4. Извлечь каждый пакет в изолированный промежуточный каталог с возможностью
   продолжения либо использовать распакованное дерево без запуска extractor.
5. Скопировать или связать base с `merged/app.partial`; наложить обычные patch
   в порядке целочисленных версий, а затем явно обозначенный слой backport той
   же версии.
6. Для выбранного распакованного источника автоматически проверить
   `sce_sys/npbind.dat` уже во временной объединённой копии. Если структура
   файла корректна, а ошибочен только 20-байтовый SHA-1-футер, заменить
   исключительно этот футер. Исходное дерево и все байты до футера остаются
   неизменными; повреждение структуры не маскируется таким исправлением.
7. Оставить обычную обработку DLC отключённой по умолчанию. Если пользователь
   явно включает экспериментальный режим единого образа, сохранить каждое
   выбранное дополнение в изолированной промежуточной области, отклонить
   точные дубликаты, не накладывать метаданные `sce_sys` DLC на игру и
   подготовить для игрового расположения `/app0` только временные копии.
   `PSAC` обозначает DLC с данными, а `PSAL` — DLC только с лицензией.
8. Добавить или проверить метаданные ShadowMount, не заменяя `param.sfo`;
   перенести в `param.json` все имеющиеся локализованные `TITLE_00…29` и
   ненулевые пользовательские параметры, сохранив остальные поля JSON.
9. Потоково записать внутренний exFAT во внешний PFSC официальным
   зафиксированным MkPFS.
10. Проверить контейнер PFSC, извлечь и проверить только обязательные пути
    метаданных, затем атомарно опубликовать результат.

Экспериментальная ветвь DLC может менять временные копии исполняемых файлов
игры и добавлять вспомогательные файлы в объединённое дерево. Она никогда не
записывает изменения в исходные PKG или выбранный распакованный источник.
Проверка на компьютере подтверждает только внутреннюю согласованность
контейнера и ожидаемых файлов; обнаружение прав на DLC и поведение игры на PS5
остаются `runtime_verified=false` до проверки на консоли. Успешная сборка не
гарантирует запуск игры или работу DLC.

Обычный путь сборки не вычисляет хеши содержимого исходных PKG, извлечённых
деревьев, деревьев объединения или готового образа. Идентификаторы продолжения
используют путь, размер и время изменения; состояние дерева — пути, размеры и
время изменения. Явная команда `verify` по запросу всё ещё может вычислить
SHA-256 артефакта.

Файлы распакованного источника подготавливаются с
`consume_source=false`. Предпочтительна жёсткая ссылка в пределах одной
файловой системы, иначе файл копируется. Очистка ограничена временным корнем
игры, принадлежащим приложению, поэтому выбранный dump не может быть
перемещён или удалён ни при успешной, ни при неудачной сборке. Атомарная
замена исправленного футера `npbind.dat` также происходит только внутри этого
временного корня.

Прогресс извлечения в интерфейсе вычисляется без сканирования промежуточного
дерева. Нативный helper сообщает фактическое число записанных байтов и
ожидаемый объём распакованных данных; Python преобразует отношение для каждого
пакета во взвешенный по размеру исходного PKG общий прогресс base, patch и DLC.

Все подпроцессы получают массивы аргументов и используют `shell=False`. При
`--all` ошибка одной игры изолирована. Приоритет кодов выхода: нехватка места
`5`, ошибка проверки `4`, общая ошибка pipeline `1`, пропущенный конфликт `2`,
неподдерживаемый пакет `3`; побеждает наиболее серьёзный достигнутый этап.
